     GRADE-FAKE-01 · Fake grading endpoint and full grading loop

     Context

     Screen 2 currently shows 8 question cards with empty mark boxes and no
     "Grade with AI" button. This ticket wires the full grading loop end to
     end using a fake /api/grade endpoint that returns a fixed,
     hardcoded result per question — so the UI, progress bar, and totals all
     work and feel real before the real AI call (GRADE-01) is plugged in.
     The fake endpoint's response shape must match the real one exactly, so
     GRADE-01 can swap it in later with no UI change.

     Design decision (confirmed with human)

     The fake endpoint needs a deterministic way to prove the failure path
     (a "cannot grade" result) without flakiness. Chosen approach: hardcode
     one fixed canned result per question id (Q1–Q8). Q6 always returns the
     cannot-grade shape (mark: 0, needsReview: true); the other 7 always
     return a fixed placeholder mark/feedback (needsReview: false). Q6 is
     answered by all 4 students, so clicking "Grade with AI" on any student
     reliably shows one failed card, both for manual testing and for a unit
     test that calls the route directly.

     Files to change

     lib/validation/schemas.ts (add, don't touch existing schemas)
     - GradeRequestSchema: { questionId, question, rubric, modelAnswer,
       maxMarks, response } — everything the real grading call (GRADE-01) will
       need, so this ticket's shape is a drop-in match.
     - GradeOutputSchema: { mark: number (int, >=0), feedback: string,
       needsReview: boolean }.
     - Export the inferred types (GradeRequest, GradeOutput).

     app/api/grade/route.ts (new)
     - POST handler: parse body with GradeRequestSchema.safeParse; on failure,
       400 with a clear message (same "validate at the boundary" pattern as the
       existing routes).
     - A hardcoded lookup object, one entry per question id Q1..Q8, each a fixed
       GradeOutput. Q6's entry is the cannot-grade shape (mark: 0, feedback:
       "Could not grade this response automatically.", needsReview: true). The
       other 7 each get a fixed placeholder mark (full marks) and feedback,
       needsReview: false.
     - Look up by questionId from the parsed body; if somehow unknown (shouldn't
       happen with real data), fall back to the same cannot-grade shape rather
       than guessing — no silent failure.
     - Validate the outgoing object with GradeOutputSchema.parse before
       returning it (cheap guarantee the fake always matches the contract
       GRADE-01 must also satisfy).

     lib/state/GradingContext.tsx (extend the existing reducer, no breaking
     changes)
     - Add three actions:
       - START_GRADING { student, total } → sets gradingProgress = { student,
         done: 0, total }.
       - QUESTION_GRADED { student, questionId, mark, feedback, needsReview } →
         writes those three fields onto that question's result, bumps
         gradingProgress.done by 1 (only if gradingProgress.student ===
         student).
       - FINISH_GRADING { student } → clears gradingProgress back to null (only
         if it matches that student, to avoid a race if the tutor navigates away
         mid-grade).
     - No changes to QuestionResult, QuestionStatus, or the selectors —
       getStatus/getTotal already derive "Marked" and totals from mark/status,
       so Screen 1's row updates for free once marks land.

     lib/state/gradeStudent.ts (new)
     - async function gradeStudent(student, questions, dispatch, callGradeApi =
       defaultCallGradeApi).
     - Filters to questions where status !== "no_submission" (invariant I4:
       no-submission never calls the API).
     - Dispatches START_GRADING with the gradeable count.
     - For each gradeable question, in order: call callGradeApi(question), then
       dispatch QUESTION_GRADED with the result and bump progress.
     - callGradeApi wraps fetch("/api/grade", ...); if the fetch throws or the
       response isn't OK, catches it, logs the question id (no response content,
       per the no-PII-in-logs rule), and dispatches the same safe fallback
       (mark: 0, needsReview: true, feedback: "Could not grade this response.")
       so the loop never crashes and always continues (this covers genuine
       network failure, separate from Q6's canned cannot-grade shape).
     - Dispatches FINISH_GRADING after the loop.
     - callGradeApi is an injectable parameter so tests can pass a fake instead
       of mocking global fetch, matching the project's "mock only external
       services" testing rule.

     app/student/[name]/page.tsx (edit)
     - Add a "Grade with AI" button. Disabled while gradingProgress?.student ===
       name (prevents a second overlapping run on the same student;
       retriggering after it finishes is fine, grading is idempotent per the
       spec).
     - On click: call gradeStudent(name, Object.values(questionResults),
       dispatch).
     - While gradingProgress is set for this student: show an animated progress
       bar + "Grading {done} of {total}..." text (simple div width transition,
       inline in this file — no new component file, nothing else reuses it).
     - Card rendering: show mark !== null ? \${mark} / ${maxMarks}` :
       (no-submission ? "0" : "–"), the feedback text once present, and a
       visible "Needs review" badge when needsReview` is true (so Q6's failure
       is visibly different from a normal graded card, not a crash).
     - Show the running total (getTotal) near the heading, same pattern Screen 1
       already uses — no new selector needed.

     Tests (new files, matching the ticket's thin table)

     - tests/grade-student.test.ts: build Diego's QuestionResult[] the same way
       the existing grading-state.test.ts does (via getStudentSubmission + the
       local initExam helper), run gradeStudent with an injected fake
       callGradeApi, assert:
       - exactly 2 calls made (Q2, Q6), 6 skipped (I4).
       - after the loop, getTotal on the resulting state returns the correct
         awarded/max (I5).
       - when the fake callGradeApi throws for one question, the loop still
         finishes all gradeable questions and that question ends up needsReview:
         true, mark: 0 (failure path, no crash).
     - tests/api-grade.test.ts: call the route handler directly.
       - valid body for a normal question (e.g. Q2) → 200, shape matches
         GradeOutputSchema.
       - valid body for Q6 → 200, cannot-grade shape (mark: 0, needsReview:
         true).
       - malformed body (missing field) → 400.
