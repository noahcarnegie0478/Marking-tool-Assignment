     The ticket's own risk note is the thing to get right: both screens must be

     app/page.tsx and app/layout.tsx are still the default create-next-app

     State store

     lib/state/GradingContext.tsx (new, "use client")
     - QuestionResult type — extends the existing QuestionWithResponse shape
       from
       lib/exam/loadExam.ts with grading fields, so there's one source of truth
       per
       question instead of two parallel structures:
     type QuestionResult = QuestionWithResponse & {
       mark: number | null;        // null until graded
       feedback: string | null;
       needsReview: boolean;
     };
       status stays "no_submission" | "pending" for now (matches the type
       already
       narrowed in loadExam.ts — the last reviewer flagged reaching ahead into
       "grading"/"graded" before they're produced; GRADE-FAKE-01 extends this).
     - GradingState:
     type GradingState = {
       results: Record<string, Record<string, QuestionResult>>; // student ->
     questionId -> result
       gradingProgress: { student: string; done: number; total: number } | null;
     };
       gradingProgress is part of the state shape now (the ticket asks for it
       explicitly) but nothing sets it yet — that's GRADE-FAKE-01.
     - One action for this ticket: { type: "INIT_EXAM"; submission:
       StudentSubmission }.
       Reducer builds results[submission.name] by mapping each question to a
       QuestionResult with mark: null, feedback: null, needsReview: false.
     - GradingProvider wraps children in createContext + useReducer.
     - useGrading() hook reads the context (throws a clear error if used outside
       the provider — a real bug, not a case to hide).

     lib/state/selectors.ts (new, pure functions, no I/O — matches tech-spec
     §8.2)
     - getStatus(results, student): "Marked" | "Not marked" — "Marked" only once
       every question is either no_submission or has a non-null mark. Unknown /
       not-yet-visited student → "Not marked".
     - getTotal(results, student): { awarded: number; max: number } | null —
       null when the student hasn't been initialised yet (so Screen 1 shows a
       dash
       before anyone has opened that student). Once initialised: awarded sums
       mark ?? 0, max sums maxMarks, across all 8 questions (no-submission
       questions count as 0 awarded but their marks still count toward max).

     Wiring

     app/layout.tsx — wrap {children} in <GradingProvider>. Layout itself
     stays a server component; only the provider and the two pages are client.

     app/page.tsx (Screen 1, rewritten, "use client")
