     - @anthropic-ai/sdk and zod are installed
     - Node is v22.23.3, so node --env-file=.env works with no new dependency

     Approach

     Write one temporary script: scripts/smoke-test.mjs

     - Reads process.env.ANTHROPIC_API_KEY and process.env.MARKING_MODEL
     - If ANTHROPIC_API_KEY is missing, print a clear message
       ("ANTHROPIC_API_KEY is not set. Add it to .env.") and exit with code 1 —
       no hang, no stack trace
     - If MARKING_MODEL is missing, same treatment
     - Otherwise, call anthropic.messages.create with one hardcoded prompt
       (e.g. "Say hello in exactly five words.") and print the reply text to
       the console
     - Wrap the call in try/catch so an API error (bad key, wrong model name)
       also prints a clear message instead of an unhandled exception
     - The key's value is never printed or logged anywhere. Only two things
       ever reach the console: the model's reply text, and static messages like
       "key not set" / "call failed". ANTHROPIC_API_KEY's value is read once
       into the SDK client constructor and nowhere else.

     Run it with:
     node --env-file=.env scripts/smoke-test.mjs

     No npm script is added for this — it's disposable, so the run command is
     just stated in the ticket report, not wired into package.json.

     Steps

     1. Create scripts/smoke-test.mjs as described above
     2. Run it with a valid key → confirm real model text is printed
     3. Run it with ANTHROPIC_API_KEY temporarily unset → confirm the clear
        error, not a hang (can simulate by running node scripts/smoke-test.mjs
        without --env-file, so the var is genuinely absent)
     4. Delete scripts/smoke-test.mjs once both checks pass — ticket's extra
        Definition of Done requires the file gone from the final diff
     5. Report back: what ran, the real console output for both cases, and
        confirmation the file was deleted
